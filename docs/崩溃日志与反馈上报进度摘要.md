# 崩溃日志与反馈上报 — 进度摘要

> 分支：`fix/commit-review-edits-before-package`（后续建议拆到独立分支提 PR）
> 状态：核心实现完成，已通过编译与单测；UI 冒烟与 Windows 线构建待验证。

## 要解决的问题

生产（release）包之前**完全没有日志和崩溃捕获**：`quizpane::diagnostic` 被
`QUIZPANE_DIAGNOSTIC_LOGGING` 编译期门控，release preset 强制 OFF。用户崩溃或
出问题时拿不到任何现场。

本次实现（与用户确认的方案）：

1. Release 包默认开启日志与崩溃捕获，**只记 warning+**，用户可在设置里关
2. 日志 **rotating**（5 MiB × 2 份历史，现有口径），落在
   `GenericDataLocation/QuizPane/logs`（两个 app 都是绿色版，不存在
   Program Files 只读问题，不怼安装目录）
3. 两个 app 各加「问题反馈」入口：环境信息 + 最近日志尾 200 行（脱敏）+
   24h 内崩溃产物（Win minidump ≤5 MiB / POSIX 文本栈 ≤1 MiB），用户确认后
   POST `https://xutianyou.cc/quizpane/api/feedback`
4. 隐私：Bearer/ApiKey 脱敏（复用既有口径）+ 用户路径截断到末两级；不含
   用户名/机器名/题目内容；默认不自动上传，必须用户点击

## 已完成的改动

### core（`quizpane_core` 静态库，两个 app 共享）

- `diagnostic_logger.cpp/hpp`：拆出 `QUIZPANE_PROD_DIAGNOSTICS` 编译开关
  （新 CMake 选项 `QUIZPANE_ENABLE_PROD_DIAGNOSTICS`，默认 ON）。
  - DEBUG 语义不变（info 全量、verbose payload）
  - PROD：Qt 消息只落 warning+；`event()` 面包屑常落；崩溃捕获常装
    （Win SEH+minidump / POSIX signal+backtrace，POSIX 崩溃时现开 fd）
  - 运行时开关：QSettings 键 `diagnosticsEnabled`（默认开），
    `isDiagnosticsEnabled()/setDiagnosticsEnabled()`；关闭即停写盘，
    崩溃 handler 读 atomic 缓存避免触碰 QSettings
  - PROD 下日志额外做路径脱敏（`maskPaths`）
  - `shutdown()` 恢复 Qt 原生消息处理器
- `feedback_report.cpp/hpp`（新增）：
  - `buildEnvironmentInfo()`：应用名/版本/OS/架构/Qt 版本/磁盘剩余/最近崩溃
    存在性与时间（不含用户名、机器名、完整路径）
  - `buildLogTail(200)`：日志尾 200 行，Bearer/ApiKey + 路径双重脱敏
  - `sendReport()`：组装 JSON → POST，30s 超时，HTTP 状态映射成用户文案

### 两个 app

- `desktop-qt`：
  - `ui::showFeedback()`（app_dialogs）：描述必填（空则禁用发送）、
    勾选项「附日志」「附崩溃信息」、隐私提示文案
  - 菜单入口 3 处：托盘、macOS 原生应用菜单、主窗口菜单
  - 主窗口菜单新增「记录诊断日志」勾选开关
- `bank-studio`：
  - `StudioWindow::showFeedbackDialog()`：同样式对话框
  - 设置菜单入口 + 「记录诊断日志」勾选开关

### 服务端

- `release-proxy/quizpane-release-proxy`：新增 `POST /api/feedback`
  - JSON schema 校验（描述 ≤8000 字符、日志 ≤2 MiB、崩溃 ≤6 MiB）
  - 整包 >8 MiB → 413（读完剩余字节再回 413，避免 100-continue 断流）
  - 落盘 `FEEDBACK_DIR`（默认 `./data/feedback`，生产
    `/var/lib/quizpane/feedback`，0600），启动时按
    `FEEDBACK_RETENTION_DAYS`（默认 30 天）清理
- `deploy/nginx/quizpane.conf.template`：`/api/feedback` 与
  `/quizpane/api/feedback` 单列 `client_max_body_size 8m`
- `deploy/env/release-proxy.env.example`：`FEEDBACK_DIR` /
  `FEEDBACK_RETENTION_DAYS`（目录已在 systemd ReadWritePaths 内，无需改单元）
- `docs/官网静态页与Release代理部署方案.md`：路由表 + 运维说明

## 已知设计取舍

- 反馈发送是**同步**的（临时事件循环 + 30s 超时），对话框期间主线程阻塞，
  换取实现简单；日志只取尾部 200 行控制体积
- POSIX 崩溃产物是文本栈（无 minidump 等价物），Win 才有 .dmp
- 服务端不做二次脱敏，按「用户主动提供的支持材料」对待（客户端已脱敏）
- 无鉴权：上报端点公开，靠 schema 校验 + 8 MiB 上限 + 落盘 30 天自清理
  控制风险；如后续被刷可加 nginx `limit_req`
