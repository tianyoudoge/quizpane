# 01 · 总览：应用结构与数据流

## 1. 应用布局

题库制作器是独立 Qt Widgets 应用 `apps/bank-studio`，分两层：

- **engine/**（纯逻辑，无 UI 依赖）：文档提取、规则解析、MinerU 客户端、生成工作流。
  - `include/quizpane/studio/*.hpp` + `src/*.cpp`
- **src/**（UI 层）：四步向导窗口、复核编辑、打包导出。
  - `studio_window.cpp`（3112 行，主控制器）、`source_row_widget.*`（第一步资料行）、
    `review_draft_bank.*`（复核草稿构造）、`source_validation.hpp`（格式白名单）、
    `mineru_settings_dialog.*`（MinerU 配置）。

四步向导：`01 选择资料 / 02 自动整理 / 03 检查问题 / 04 完成`
（`studio_window.cpp:621-622` 侧栏定义，`studio_window.cpp:666-671` `QStackedWidget` 装配）。

## 3. 核心类型

### 3.1 ExtractedDocument（提取统一产物）

`document_extractor.hpp:39-74`。本地提取与 MinerU 云提取都产出这一结构，下游规则引擎只认它：

| 字段 | 说明 |
|---|---|
| `sourcePath` / `plainText` / `error` | 错误非空 = 该文件不可用（区别于"文档无内容"，`:36-38`） |
| `warnings` | 可恢复的逐页问题（如某页 OCR 失败） |
| `hasPageBoundaries` | 文本按 `\f` 换页符分隔（PDF/OCR 才有），驱动 `source.page` |
| `extractionBackend` | 空/`local-qt` = 本地；`mineru-<backend>` = 云端。规则引擎**只用它启用**"经云端坐标验证"的能力（四选项裁图、句尾横线修复），不解析 MinerU 原始 JSON（`:49-52`） |
| `usedOcr` | 有页走 OCR 即 true，仅作软复核信号，不改解析路径 |
| `ocrSkippedPages` / `ocrFailedPages` | 区分"构建未启用 OCR"与"OCR 失败"（`:55-58`） |
| `pageImages` | 扫描页提取时立即保留渲染 PNG；文字页按需懒加载（`ensurePdfPageImages`） |
| `questionAnchors` / `optionLabelAnchors` | 每页题号、A-D 选项标签的归一化(0..1)坐标 |
| `lineAnchors` | 每页每行文字坐标（材料裁图、视觉行重排、漏题号恢复依赖它） |
| `underlineDecorations` | 下划线/空白横线几何检测结果（按需触发，见 02） |
| `sectionId` / `sectionTitle` / `firstPageNumber` | 套题切分后每套的元信息（保持原始绝对页码） |
| `companionAnswerText` / `companionAnswerSourcePath` | 独立答案册的伴随文本与来源；分套后再按套题标题分发 |

### 3.2 ReviewResult（生成统一产物，两条链路共用）

`review_result.hpp:13-26`。规则与模型路径都输出它，workflow 不维护第二套降级语义：

| 字段 | 说明 |
|---|---|
| `materials` | 共享材料（阅读/资料/题组），QJsonArray |
| `questions` | 可直接采用（ok）+ soft 复核题（结构保留，默认勾选） |
| `needsReviewQuestions` | hard 风险题：保留原始识别 + 失败原因，**禁止猜测答案** |
| `warnings` | 整批警告（漏题号区间等） |
| `assets` | `assets/<...>.png → PNG 字节`，**正式附件，写入安装包** |
| `hasAnswerKey` | 整库二选一（含答案/无答案），不允许混合 |
| `answerEvidenceDetected` | 是否识别到可靠答案证据；供 Auto 策略选择最终 `hasAnswerKey`，不写入 bank.json |
| `reviewSourceImages` | 题 id → 原卷裁图描述，**仅校对用，不进 bank.json** |
| `reviewAssets` | 校对裁图字节（与正式附件分开，避免"每题一张预览图"撑大安装包） |

### 3.3 bank.json（最终题库格式）

Schema 文件：`schemas/declarative-provider.schema.json`（176 行）；**运行时权威契约是 C++ 校验器**
`core/src/bank_validator.cpp`（制作器与 CLI 都调 `quizpane::validateBank`）。

```jsonc
{
  "schemaVersion": 3,
  "title": "题库名",
  "answerPolicy": "included | none",          // 整库二选一
  "catalogs": [{ "id": "generated", "title": "…",
                 "practice": { "mode": "all | sequential", "questionCount": 5 } }],
  "questions": [{
    "id": "r0-q44-17",                        // 引擎生成，不可改
    "catalogId": "generated",
    "type": "single_choice | multiple_choice | true_false",  // bank_validator.cpp:23
    "stem": "题干（≤20000 字，含〔填空〕占位）",
    "stemUnderlines": [{"start": 12, "length": 4}],          // 可选
    "options": [{ "id": "a", "text": "…(≤4000)",
                  "image": { "path": "assets/…", "alt": "…" } }],  // 2–20 项
    "answer": { "optionIds": ["a"] },          // answerPolicy=included 时必填
    "solution": "解析",
    "aiSolution": "用户生成的 AI 解析 HTML（可选，与标准答案独立）",
    "materialId": "r0-m1",                     // 可选，引用共享材料
    "source": { "document": "文件名", "page": 3,
                "questionNumber": 44 | "1-1", "questionLabel": "44",
                "sectionId": "set-2", "sectionTitle": "实战演练二" },
    "review": { "needsReview": false, "confidence": 0.95,
                "riskLevel": "ok | soft | hard", "signals": ["image-content"] }
  }],
  "materials": [{ "id": "r0-m1", "title": "…", "body": "…",
                  "underlines": [...], "images": [...],
                  "source": { "document": "…", "page": 1 } }]
}
```

`source.questionNumber` 从 2026-08 起兼容正整数和非空字符串：整数覆盖传统 `1/2/3` 题号，
字符串保留 `1-1`、`（一）` 等无法无损转成整数的原卷标签；`questionLabel` 仍可提供更适合展示的文案。
`DeclarativeProvider::hostQuestions` 不再把字符串题号强转为 0，作答页、解析页和结果长图统一优先展示标签。
结果长图在预览窗口设置 pixmap 后会同步刷新 `QLabel` 尺寸，使滚动区按完整图片大小布局，避免只显示左上角色块。
结果图按当前页懒生成，只保留一张原始图片和预览 pixmap；翻页先释放旧图，避免一次性
持有所有结果页。导出打开时固定题目、作答和时间快照，翻页不会混入后续练习状态。
结果图固定为适配预览区的 680px 宽、两列卡片，不再依赖横向滚动查看；无答案题库达到 5 题时，
按每 5 题合并为一项（如 `1–5题  AABBC`），未作答显示 `?`，多选以 `[AC]` 保留答案边界。

### 3.4 小窗刷题的组卷兼容层

- `DeclarativeProvider::expandSectionCatalogs` 在加载后检查同一 catalog 下的
  `source.document + source.sectionId`。存在两套以上时，仅在内存中展开成“每套一个 catalog”，
  套名取 `sectionTitle`；老的 `bank.json` 不需要迁移，且不同文件里同名 `set-1` 不会误合并。
- 跨套共享同一 `materialId` 时保持原 catalog，不做可能破坏题目/材料外键的自动拆分。
- `answerPolicy=none` 时，运行时把旧题库配置的 `practice.mode=random` 收紧为顺序模式；
  题目仍按 bank 中的原始次序组成练习，便于整套做完后对照外部答案。

**附件描述符**允许 `path/alt/sourceDocument/sourcePage/autoCrop/crop` 六个键
（`bank_validator.cpp:73-92` validAsset；`autoCrop`/`crop` 是 0..1 归一化裁切框）。
⚠️ JSON Schema 文件的 `$defs.asset` 仍写 `additionalProperties:false` 只放行 `path/alt`，
**以 C++ 校验器为准**（schema 文件滞后）。

题型支持现状：运行时校验接受 `single_choice / multiple_choice / true_false`
（`bank_validator.cpp:23`）；多选可由规则引擎产出（section 标题传播多答案时），
主程序已实现多选的选项切换、草稿/提交数据、判分和结果展示
（`apps/desktop-qt/src/ui/main_window.cpp:1246-1269,1310-1327,1395-1404,1503-1520`）。
`docs/题库生成器UI与集成方案.md:92` 仍写“待实现”，属于历史文档滞后。

## 4. 两条识别链路的分工（重要）

| | 规则识别 | 智能识别（MinerU） |
|---|---|---|
| 定位 | 解析器（把文本切题） | **提取后端**（把 PDF 变成 ExtractedDocument） |
| 运行位置 | 本地，纯离线、确定性 | 云端服务，本地只是 HTTP 客户端 |
| 失败行为 | 结构异常题进 needsReview 人工复核 | 提取失败 → 该文件 Failed，**不降级到模型** |
| 共同点 | 都输出 ReviewResult；都支持同四种答案位置语义；都走同一复核 UI | 同左 |

也就是说：**"智能识别"不是"模型理解题目"，而是"用 MinerU 的版面分析能力提取文本和坐标"，
提取之后仍然走规则引擎切题**。详见 [04-智能识别链路-MinerU.md](04-智能识别链路-MinerU.md)。

## 5. 全局设计约束（vibe coding 前必读）

1. **确定性**：规则引擎同输入同输出；统计类审计有最小样本量门槛（`rule_based_generator.cpp:2100-2187`）。
2. **宁缺毋滥**：答案错位写入比不写入更有害；多处"数量不匹配 → 不绑定 → 题进复核"（`:1447-1448`、`:2549-2553`）。
3. **归一化用 NFC 不用 NFKC**：NFKC 会把圈码 ① 分解成裸 1，丢失选项标记（`rule_based_generator.cpp:796-802`）。
4. **来源信息只记文件名/页码/归一化坐标**，不含本机绝对路径（`visualAssetDescriptor` `:329-333`）。
5. **校对图不进安装包**：只有 `assets`（正式附件）打包；`reviewAssets` 是制作期临时数据。
6. **编辑不产生新 id**：用户编辑只是原地改 `QJsonObject` 字段；`id` 格式 `r<文档序>-q<原始题号>-<全局递增>`（`:2673-2676`）。
7. **hasAnswerKey 整批一致**：Auto 先按含答案完整探测；检测不到答案证据时才重跑为无答案库。人工 Included/None 是整库覆盖；无答案库不写 `answer`/`solution`。

## 6. 作答后 AI 解析（可选）

解析页的“AI 解析”由 `SolutionPageController` 按当前题目发起；
解析页将单段落文字选项与字母排在同一行，保留复杂 HTML 和选项图片；
题库未提供原始解析文字或图片时隐藏空的“解析”块，AI 解析仍独立显示。
已有原解析时，AI 卡片紧接原解析展示，不在两者之间留下弹性空白。
旁边的设置按钮允许随时修改供应商、密钥、地址和模型；自定义供应商必须填写地址与模型。
全局菜单和托盘菜单提供“AI 解析设置…”；macOS 原生菜单也提供同名入口，
未加载题库或未进入解析页时即可配置。所有入口由 `MainWindow` 复用
`SolutionPageController::showAiConfigDialog`，与解析页按钮共享同一份 `AppSettings` 配置。
将密钥清空并保存会移除已保存的密钥；下次请求 AI 解析时重新提示配置。
`AiExplainService` 将材料正文、题干、选项和题库提供的标准答案发送到用户配置的兼容
Chat Completions 接口，并把材料图片、题干 HTML 图片、选项图片读取为 base64
`image_url` 内容块。发送前去除 HTML 中的本机图片路径；图片缺失、损坏、格式不支持
或超出大小限制时明确失败，不会退回纯文字解析。旧版预设的纯文本模型遇图片时切换为
对应供应商的视觉模型；自定义模型需由用户配置为支持图片的模型。
DeepSeek 请求允许最多 128K 个输出 token，以覆盖推理模型在生成正文前消耗的推理 token；
其他供应商的视觉请求上限为 8192，纯文字请求为 2048。提示模型用 Markdown 排版正文
（加粗、`- ` 列表），所有数学内容写成 `$…$`／`$$…$$` 中的 LaTeX，分数用 `\frac`。
解析提示要求模型区分交叉分类口径：仅能确定上下界时用不等式判断，不能把界限
描述为精确统计值。
无答案题库明确告知模型“未提供”，模型结论不作为题库答案。
生成成功后，声明式题库将 AI 正文写入已安装的 `content/bank.json` 中对应题目的
`aiSolution`，通过 `QSaveFile` 原子替换并先执行整库校验；此字段在含答案和无答案
题库均可选，不改变 `answer`、原始 `solution` 或全库答案策略。切题后和重开题库时
解析页恢复已生成内容，用户可主动重新生成；写入失败时明确提示，并在当前会话
保留解析。原生插件没有可写的 `bank.json`，只能在当前会话回看，界面会提示未落盘。
`AiExplanationStore` 的保存与加载入口位于 `apps/desktop-qt/src/ai/ai_explanation_store.cpp`；
数据白名单与长度约束由 `core/src/bank_validator.cpp` 和
`schemas/declarative-provider.schema.json` 同步约束。
切题时取消未完成请求，旧题响应不得覆盖当前题。服务端空响应或网络失败在解析面板
展示错误，不计入成功用量。`formatAiResponse` 将常见 Markdown/LaTeX 片段转换为
Qt 富文本，包括常见三角函数；不支持的 LaTeX 命令保留原文，不能当作完整 TeX 排版器。
入口见 `apps/desktop-qt/src/ui/solution_page_controller.cpp`、
`apps/desktop-qt/src/ai/ai_explain_service.cpp`；基础回归见
`tests/solution_page_controller_test.cpp`、`tests/ai_explain_service_test.cpp`、
`tests/ai_explain_multimodal_test.cpp`、`tests/ai_explanation_store_test.cpp`。
练习页题干中的常见 `$...$` 公式仍由 `quizpane::formatQuestionHtml`
（`apps/desktop-qt/src/ui/formula_formatter.cpp`）转换；结果页题干、选项和原解析由
`quizpane::ui::formatQuestionHtml`（`ai_response_format.cpp`）转换。
两者仅转换 HTML 文字节点，保留图片路径与标签属性；AI 内容由
`ui::formatAiResponse` 转换，不提供完整 TeX 排版。
主程序构建必须同时包含两个格式化器，避免练习页调用旧入口时出现链接缺失；
验证须构建 `quizpane` 主程序，仅构建控制器测试无法发现主程序源文件清单遗漏。
小窗的“背景可见度”调节题目卡片和内部蒙版：100% 时主卡片完全不透明，
避免底层窗口文字透入题干与解析；0% 时卡片与蒙版消失，文字仍保持可读。
深浅主题的卡片基色由 `apps/desktop-qt/resources/desktop.qss` 与
`desktop-light.qss` 定义，滑块透明度由 `MainWindow::applyCardStyle` 统一覆盖。
Windows 主程序启动时优先使用已安装的 `Microsoft YaHei`／微软雅黑；未安装则保留
系统默认字体。选中的字族记录在应用属性 `windowsUiFontFamily`，
`MainWindow::applyCardStyle` 每次刷新时显式写入字族，避免透明度或字号调整后回退。
该函数在深浅主题后加载 `desktop-windows.qss`，
题干、选项、共享材料、原解析与 AI 解析按小／中／大模式使用 13／14／15px 常规字重，
标题及富文本中的重点仍加粗，导航控件保留原紧凑字号。AI 段落、分节和列表项的
间距在 Windows 分别为 8／12／6px；公式继续按 AI 标签实际字体重新排版。
练习页题干及解析页题干、选项和原解析的容器不写死内联文字颜色，由主题 QSS 控制，
保证切换浅色模式后仍有足够对比度。
`makeLineIcon` 的绘制引擎按当前主题重绘菜单、导航和材料折叠图标，浅色使用深色线条，
禁用态降低透明度；切换主题时已有图标同步刷新。
多模态测试还可用 `QUIZPANE_Q119_BANK` 指向本机
展示错误，不计入成功用量。`ui::formatAiResponse`（`ai_response_format.cpp`）把 Markdown
转为 Qt 富文本，公式交给 `math_formula.cpp` 的小型排版器：分数上下叠放、根号、上下标、
随内容拉伸的括号和常用符号用 QPainter 画成 PNG，以 `data:` URI 内嵌，并按 Qt
`vertical-align:middle` 的实测规则补白，使公式基线与正文对齐；只有单个变量或
不等式这类无二维结构的公式输出斜体 HTML，不撑高行距。不依赖 WebEngine，Win7 可用。
