## 一、功能定位

做题是刷题端的核心交互。`MainWindow`（`apps/desktop-qt/src/ui/main_window.hpp`，实现 2987 行）
是一个**页面状态机**：用 `QStackedWidget` 承载 5 个页面（登录/引导、目录、做题、解析、可选的课程陪伴页），
所有做题数据通过 `ProviderLoader` 以 JSON-RPC 向当前题库请求。

MainWindow 本身**不含题目/组卷/判分逻辑**——它只负责渲染页面、收集用户输入、发起 RPC、
把回包画到界面上。真正的组卷和判分在题库侧（`DeclarativeProvider`）。这与服务端"Controller 只编排、
Service 出业务"的分层一致。

## 二、关键状态与所有权

`MainWindow` 的成员分三类（见 `main_window.hpp:136-257`）：

1. **应用服务**（值成员，`MainWindow` 直接拥有，析构逆序）：
   `services_` 里的 `ProviderLoader& provider_`、`DraftStore& draftStore_`、`ProviderInstaller& installer_`。
2. **控件引用**（裸指针，所有权在 Qt 父子对象树）：那一大片 `QLabel*` / `QPushButton*` / `QStackedWidget*`。
   parent 析构时自动删除，**不要手动 delete**。
3. **当前会话状态**（切题库时重置）：`providerId_` / `attemptId_` / `questions_` / `solutions_` /
   `answers_`（`QVector<QSet<int>>`，单选存大小为 1 的集合、多选存完整集合，唯一来源）/
   `currentQuestionIndex_`。**安全凭据不放这里**（凭据由 SecretStore 管）。

> 值得学习的一处细节：`materialsById_`（`main_window.hpp:241`）是 `questions` 与 `solutions`
> 两份材料数组合并后的缓存，避免每次切题都在数组里线性查材料。同类缓存在题库侧还有一层
> （`DeclarativeProvider::materialsById_`），两层各解决不同粒度的重复解析。

## 三、端到端流程（对照复杂版泳道图）

三条泳道：UI（`MainWindow`）⇄ 应用服务（`ProviderLoader`）⇄ 领域（题库 `DeclarativeProvider`）。
每一步都是 UI 发起 `request(QJsonObject)`，经 C ABI 到题库，题库应答后经 `responseThunk` →
Qt 信号 `responseReceived` 回到 `handleProviderResponse` 路由（按 `response.id`）。

| 阶段 | UI 入口 | RPC 方法 | 题库侧动作 |
|---|---|---|---|
| 加载题库 | `loadProvider` → `sendInitialize` | `provider.initialize` | 校验 manifest+bank、`expandSectionCatalogs` |
| 目录页 | `requestCatalog` → `populateCatalog` | `catalog.list` | 一次遍历累计掌握度，查 `questionCountByCatalog_` |
| 开始练习 | `startAttempt` | `attempt.create` | `buildUnits` 组卷（题组整体、掌握题过滤、random 洗牌） |
| 拉题目 | `requestQuestions` → `updateMaterialsCache` → `showQuestion(0)` | `attempt.questions` | `hostQuestions(false)` + `hostMaterials()` 转 HTML |
| 逐题作答 | `chooseAnswer` → `answers_`/`multiAnswers_` | `attempt.saveAnswers`（批量） | `answers_` 内存累积（`QSet<int>` 支持多选） |
| 交卷 | `confirmSubmitAttempt` → `sendSubmit` → `requestResults` | `attempt.submit` → `attempt.report` | 判分 `answers_==expected`，回写 `QSettings` 历史 |
| 解析/结果 | `showSolution` / `exportAttemptResults` | `attempt.solutions` | `hostQuestions(true)`，仅含答案库返回答案 |

### 草稿与断点续做

- **保存**：`saveDraft()` 在切题、退出等时机调用 `DraftStore::save`。`QSaveFile` 保证原子写
  （`draft_store.cpp:60`），进程崩溃不会留半截 JSON。目录布局
  `drafts/<providerId sha256>/<attemptId sha256>.json`——每个题库一个子目录，每次练习一个文件，
  支持多草稿并存。
- **恢复**：`maybeRestoreDraft()` 通过 `DraftStore::list` 按更新时间倒序取最近草稿。
  兼容 0.2.4 以前的单文件遗留草稿（`draft_store.cpp:127`）。
- **清理**：交卷成功后 `clearAttempt` 删除对应草稿。

### 保存节流是关键设计

`attempt.saveAnswers` **不是每次点击都发**，而是切题 / 退出时批量同步（见复杂版泳道图第 5 行）。
`saveAnswers` 支持"空选择→移除该题答案"，这样取消选择也能正确落库（`declarative_provider.cpp:458`）。

## 四、重构建议

`MainWindow` 2987 行、`main_window.hpp` 有 90+ 私有方法和 60+ 成员指针，是本项目
**最重的单一类**，也是重构收益最高的地方。按优先级：

1. **【高】按页面拆分控制器**。当前一个类同时管登录、目录、做题、解析、更新、课程陪伴、
   窗口外观。建议抽出 `PracticePageController` / `SolutionPageController` / `CatalogPageController`，
   每个持有自己那组控件与状态，`MainWindow` 退化为装配器 + 页面切换。
   收益：`answers_/currentQuestionIndex_` 等做题状态收敛到一个类，
   降低"改做题逻辑却要在 3000 行里翻控件指针"的成本。

2. **【高】统一 RPC 请求/响应的路由**。目前 `handleProviderResponse` 按 `response.id`/method
   分支手工路由。建议引入一张 `method → handler` 的表（题库侧 `methodForName` 已经是这个模式，
   可对称到 UI 侧），把"发起-等待-回包"封装成一个小的 `PendingCall` 概念，
   减少散落的状态标志。

3. **【中】把窗口外观/更新/热键等"外壳"职责移出**。`checkForUpdates` / `downloadAndInstallUpdate` /
   `configureBossKey` / `applyUiSize` 等与做题无关，可下沉到 `app_services` 或独立的
   `DesktopShell` 组件。

4. **【已完成，2026-09-06】单选/多选双轨状态合一**。原 `answers_`（`QVector<int>`）与
   `multiAnswers_`（`QVector<QSet<int>>`）已合并为单一 `answers_`（`QVector<QSet<int>>`，
   `main_window.hpp:242`），单选存大小为 1 的集合。草稿文件格式（`DraftSnapshot::answers`，
   `QVector<int>`）不变，`saveDraft()`/`maybeRestoreDraft()` 在边界处做集合↔单值的转换，
   多选题的作答不跨草稿恢复保留，与拆分前行为一致。

## 五、性能建议

- **【已做，可借鉴】结果长图懒生成**：翻页时只保留一张原图和预览 pixmap，翻页先释放旧图
  （`spec/01` §3.3）。这是 Win7 低配内存优化的范例，新增大图展示时应沿用。
- **【中】`saveDraft` 频率**：确认是否存在"每次 `chooseAnswer` 都写盘"的路径。做题状态在内存，
  落盘应节流到切题/定时/退出，避免频繁磁盘 IO（尤其机械盘 / Win7）。
- **【低】材料 HTML 重复转换**：`hostMaterials`/`hostQuestions` 每次 RPC 都重新 `paragraph()`
  转 HTML。题组内切题若触发重复请求，可在题库侧缓存已转 HTML 的材料（现有 `materialsById_`
  存的是原始 JSON，可加一层 HTML 缓存）。

## 六、可读性建议

- `main_window.hpp` 的成员区已有良好中文分区注释（`---- 应用服务 ----` 等），保持。
  但 60+ 控件指针挤在一个类里，拆分后每个子控制器 10~15 个指针会显著更易读。
- `ActionMode` 有限状态机（`main_window.hpp:69`）是好实践（用枚举代替多 bool 拼状态），
  建议把"当前处于哪个页面"也提升为显式枚举而非依赖 `QStackedWidget` 的 currentIndex。
- 复杂 RPC 回包处理函数建议在函数头用一句话注明"处理哪个 method 的回包、前置状态、
  后置状态"，降低阅读跳转成本。
