# 02 · 文档提取与扫描件处理

> 代码位置：`apps/bank-studio/engine/src/document_extractor.cpp`（1011 行）+
> `include/quizpane/studio/document_extractor.hpp`。
> 提取器按扩展名分派：`ExtractorRegistry`（`document_extractor.hpp:118-127`）
> 持有 `TxtMarkdownExtractor` / `DocxExtractor` / `PdfExtractor`，`supports()` 只看扩展名。

## 1. 支持的文件格式

| 格式 | 提取方式 | 位置 |
|---|---|---|
| TXT / MD / Markdown | 本地直读，自动识别 UTF-8 / UTF-8 BOM / GB18030 编码 | `TxtMarkdownExtractor` |
| DOCX | 直接解 OOXML ZIP 里的 `document.xml`，**不依赖 Office** | `DocxExtractor` |
| PDF | QtPdf（QPdfDocument）文字层 + 按需渲染/OCR | `PdfExtractor`，`:544-625` |
| PDF（云端） | MinerU 服务解析，ZIP 结果适配成 ExtractedDocument | 见 [04](04-智能识别链路-MinerU.md) |

UI 侧白名单：`source_validation.hpp:9-16`（`acceptedSource`：txt/md/markdown/docx，
`QUIZPANE_HAS_QT_PDF` 构建时加 pdf）。

## 2. 扫描件 vs 文本 PDF：**逐页判定**，不是整本一次判定

核心循环 `PdfExtractor::extract`（`document_extractor.cpp:544-625`），每页独立决策：

```
对每一页 page：
  rawText = QPdfDocument::getAllText(page)          // :562
  if rawText 非空:
      → 文本页：走文字层路径
        collectPdfTextAnchors(...)                  // :566, 实现 :251-295
        （记录题号锚点 / A-D 选项锚点 / 每行文字坐标，全部归一化 0..1）
  else:
      → 疑似扫描页：
        pageImage = renderPdfPage(...)              // :569, 实现 :214-223
        if hasVisibleInk(pageImage):                // :570, 实现 :195-212
            OCR 识别该页                               // :571-589
```

### 2.1 渲染参数

`renderPdfPage`（`:214-223`）：**1.5 倍**页面分辨率（约 108 DPI），像素上限 5000。
⚠️ 历史文档（`docs/规则结构化题库后端处理流程CodeReview.md:76` 附近）写的是 2 倍，
当前代码已降到 1.5x 作为确定性加速点（`:215-218` 注释）——文档滞后，以代码为准。

### 2.2 空白页过滤（避免无墨迹页触发 OCR）

`hasVisibleInk`（`:195-212`）：渲染图铺白底转灰度，按 300×300 网格采样，
**暗色像素（灰度 < 235）占比 > 0.1%** 才认为页面"有墨迹"。纯空白页直接跳过。

### 2.3 OCR（Tesseract 原生 API，不启动子进程）

- 编译开关 `QUIZPANE_HAS_TESSERACT_OCR`。
- Win7 x86/x64 的本地脚本、普通 CI、Actions 和正式 Release **强制包含 OCR**，随包分发
  中英文模型。没有 `EnableOcr` / `enable_ocr` 开关；通用 Windows 打包脚本拒绝 Win7
  的 DisableOcr/DisablePdf，CMake 拒绝关闭制作器、PDF 或 OCR。非 Win7 的开发配置不受影响。
  `win7_required_features_test` 验证完整配置放行、三项任意关闭均拒绝以及非 Win7 豁免。
- `recognizePage`（`:321-381`）：语言 `chi_sim+eng`；
  先 `PSM_AUTO`，**空结果回退 `PSM_SPARSE_TEXT`**（`:372-376`，适合只有一两行的页）；
  两次都为空 → `ocrFailedPages++` + 逐页 warning（`:575-580`）。
- 模型路径 `bundledTessdataPath`（`:299-319`）查找顺序：
  环境变量 `TESSDATA_DIR` / `TESSDATA_PREFIX` → 应用目录 `tessdata/`
  → `../Resources/tessdata` → `../share/quizpane/tessdata`；
  必须同时存在 `eng.traineddata` 和 `chi_sim.traineddata`。
- 编译期未启用 OCR：`ocrSkippedPages++` + warning（`:583-588`）；
  整份文档若全被跳过 → 报错"此 PDF 有 N 页需要文字识别（OCR）…"（`:608-610`）。
- 单页 OCR 失败：该页文本置空串占位（`:578`/`:586`），**其余页继续可用**。
- Windows 启用 OCR 的绿色包在压缩前把 `document_extractor_test` 临时放进最终部署目录，
  清空构建机的模型/插件环境变量并用合成扫描 PDF 执行 `--ocr-smoke`；必须实际加载包内
  QtPdf、平台插件、静态 OCR 引擎与 `tessdata/`，通过后删除测试程序再生成 ZIP。

**`ocrSkippedPages` 与 `ocrFailedPages` 刻意区分**（`document_extractor.hpp:55-57`）：
前者是"构建没带 OCR"（不是题号格式问题），后者是"OCR 识别失败"。
规则引擎据此生成不同措辞的警告（`rule_based_generator.cpp:2626-2638`）。

### 2.4 渲染图保留策略（性能关键）

- **扫描页**：渲染 PNG 立即写入 `result.pageImages`（`:594-600`，PNG 压缩级别 1）。
- **文字页**：不预渲染。规则生成器确认某题"需要原卷视觉上下文"（图题/表题）时，
  才调 `ensurePdfPageImages`（`:966-994`）按需渲染，带页级去重缓存。
  设计意图：避免"全卷每页渲染 + PNG 压缩"拖慢普通纯文字题库。
- `pageImages` 是按字节计量的缓存（x86 预算 64 MiB，64 位预算 200 MiB；单项超预算仍保留该页）：超限后淘汰最早插入的页，
  再次需要时重新渲染。它只约束整页中间图；普通题的逐题校对图另行采用复核页按需渲染，
  不在规则整理期间批量写入 `reviewAssets`。
- 分套合订本的所有 `ExtractedDocument` 副本共享一个 `PdfRenderSession`；Qt 5.15/Win7
  不再为每套重新构造 `QPdfDocument`。Windows 渲染预算由 `pdf_memory_budget.hpp` 统一定义，覆盖
  自动题图、扫描提取、UI 原卷预览与校对拼图。x86 Private Usage + 预计图片开销不超过
  1200 MiB，同时预留 128 MiB 用户虚拟空间；系统提交预留按物理内存的 1/8 限在
  128–512 MiB，按 16 字节/像素预估渲染与转换临时开销。预算是保守初值，不是全进程
  OOM 保证，仍需 Win7 实机校准；不降低原有 DPI，也不跳过正确性校验。
- 自动题图受限仍保留文字并给复核提示；扫描渲染/灰度转换失败会产生逐页 warning，
  计入 `ocrFailedPages`，绝不当空白页静默跳过。OCR 输入图片分配失败在初始化前报错。
  普通大页 PNG 缓存不覆盖所有文档总量和第三方引擎内部内存。

### 2.5 页间边界

各页文本用 `\f` 换页符拼接（`:603`），`hasPageBoundaries = true`（`:604`）。
规则引擎按 `\f` 推进页码，生成 `source.page`（TXT/DOCX 没有稳定页码时保持 false，
避免伪造来源位置，`document_extractor.hpp:45-48`）。

### 2.6 重复页眉 / 页脚 / 页码清理

`stripRepeatedPageFurniture()` 是本地 PDF 与 MinerU 适配器共用的页级清理契约：

- 有 `lineAnchors` 时，只统计归一化 bbox 位于顶部 8% 或底部 8% 的行；数字串先替换为
  `#` 再跨页比较，因此“固定口号 + 逐页变化页码”可以归为同一项；
- 同一顶部/底部 key 必须出现在至少 `max(3, ceil(总页数×40%))` 页才删除，覆盖整本固定
  页眉以及奇偶页交替页眉，同时避免把只在少数页恰好靠近边缘的正文误删；
- OCR 或 MinerU 缺 `page_size`、整页无坐标时，只检查至少三行页面的第一/最后一条非空行，
  且阈值提高到 `max(3, ceil(总页数×65%))`；不根据“机构名/推广语”等文案黑名单猜测；
- 清理保持 `\f` 数量不变，并同步移除被删行上的 `lineAnchors`、`questionAnchors`、
  `optionLabelAnchors`，避免后续题图裁切继续使用失效坐标；
- `PdfExtractor::extract()` 和 `adaptMineruLayout()` 分别在产出 `ExtractedDocument` 时调用；
  `RuleBasedBankGenerator::generate()` 还会幂等执行一次，约束测试夹具与未来新增提取后端。

回归覆盖：`document_extractor_test`（坐标路径、OCR 无坐标兜底、低频正文保护）和
`mineru_output_adapter_test`（`para_blocks` 被污染时的智能链路兜底）。

## 3. 版面锚点（文本页的"视觉"能力）

`collectPdfTextAnchors`（`:251-295`）对每个文本页记录三类归一化(0..1)坐标：

| 锚点 | 识别模式 | 用途 |
|---|---|---|
| `questionAnchors` | `^\s*(\d{1,4})\s*[、.．]`（`:253-254`） | 整题裁切、漏题号恢复的段距判断 |
| `optionLabelAnchors` | `(?<![A-Za-z0-9])([A-D])\s*[、.．]`（`:255-256`） | 选项图裁切 |
| `lineAnchors` | 每一行文字（`:277-294`） | 视觉行重排、材料裁图、下划线检测、漏题号恢复 |

**为什么用文字层坐标而不是 OCR 图里的坐标**（`document_extractor.hpp:14-15`）：
归一化后规则生成器可以同一套逻辑裁切任意渲染分辨率的页面，
而且不必 OCR 图片里的数学符号（公式题文字层可能不完整，但坐标可用）。

## 4. 下划线 / 填空横线检测（纯几何，按需触发）

PDF 文字层不表达"文字带下划线"样式，所以用**渲染图 + 文字选择框的几何交叉**检测：

- 数据结构 `PdfUnderlineDecoration`（`document_extractor.hpp:24-30`）：
  `text` + `ranges`（文字下划线 UTF-16 偏移区间）+ `blanks`（空白横线位置）。
  **没有足够证据就不填充，绝不根据题目选项猜测**（`:21-23`）。
- 核心算法 `detectRenderedLineDecorations`（`:386-485`）：
  在文字基线附近 ±(7%, 30%) 行高带内找暗色长线段；
  连续暗段长度 ≥ `max(6, 高度×1.03)` 才认定（minimumRun）。
- **刻意不在 `extract()` 中全卷执行**（`document_extractor.hpp:105-109`）：
  规则生成器先确认某题含"划线|画线|横线|下划线|空白处"线索（`rule_based_generator.cpp:2330-2344`），
  再把那几行材料传给 `detectPdfUnderlinesForCandidateLines`（`:627-964`），
  避免整卷逐字符扫图造成延迟和误召。
- MinerU 来源的模糊匹配：云端可能压缩空格/幻读单字符，下划线匹配用
  "去空白 key + 8 连续字符 ≥60% 覆盖"（`:647-657`、`:762-793`）；
  文字下划线要求**逐字完全一致**才转交（`:682-684`），空白横线按相邻字符序号映射（`:702-758`）。
- 检测结果的消费：
  - `ranges` → 题干 `stemUnderlines` / 材料 `underlines`（`{start,length}` UTF-16 偏移）；
  - `blanks` → `〔填空〕` 零宽插入（`rule_based_generator.cpp:1215-1226` `buildMaterialText`）；
  - 文字层丢掉的空白横线：`restoreDroppedBlankLines`（`rule_based_generator.cpp:381-394`）
    只在**汉字与紧随中文标点之间**补 `〔填空〕`；`__`/`＿＿`（≥2）统一替换。
    注意：`【甲】【乙】` 是原题编号必须保留，不是填空（`:382-383`）。

## 5. 提取失败的语义

| 情况 | 行为 | 位置 |
|---|---|---|
| 文件错误 / 格式不支持 | `error` 非空，整份文档跳过（UI 提示具体扩展名） | `document_extractor.hpp:36-38` |
| 某页 OCR 失败 | 该页空串占位 + warning，其余页可用 | `:575-580` |
| 构建未启用 OCR | 逐页 warning + 汇总提示 | `:583-588` |
| 全卷无文字层且无 OCR | 整份报错，不用空字符串冒充"文档无内容" | `:605-616` |

## 6. 已知坑

1. **CRLF**：PDF 文字层的 CRLF 若不合并成单个换行，会让每行都带 `paragraphBreakBefore`
   （`rule_based_generator.cpp:902-909`）——新增文本处理时注意。
2. **文字 PDF 也可能嵌位图**（统计图、图形推理题）：扫描页提取时保留渲染图，
   文字页按需渲染（`:59-62` 注释）；纯文本字段里没有图，图必须来自 `pageImages` 裁切。
3. **OCR 结果不可靠是常态**：所以 OCR 来源的题统一打 `ocr-source` 软复核信号
   （`rule_based_generator.cpp:2039-2040`），confidence 上限 0.75。
4. **同页重复题号**时坐标不可信：`questionBoundsFor` 直接拒绝裁切并 hard
   （`rule_based_generator.cpp:344-352`，"同页重号不能任取第一个坐标"）。
