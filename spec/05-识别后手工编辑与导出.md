# 05 · 识别后手工编辑与导出

> 代码位置：`apps/bank-studio/src/studio_window.cpp`（3112 行）、
> `src/review_draft_bank.*`、`src/source_row_widget.*`、`src/source_validation.hpp`；
> 校验器 `core/src/bank_validator.cpp`；Schema `schemas/declarative-provider.schema.json`。
> 下文 `studio_window.cpp` 行号均指该文件。

## 0. 关键前提（先记住）

1. **题目没有 C++ struct**：全链路都是 `QJsonObject`，字段契约以
   **C++ 校验器 `bank_validator.cpp` 为权威**（JSON Schema 文件滞后）。
2. **没有磁盘草稿**：复核页编辑全部驻留在 `QTreeWidgetItem::UserRole` 的 `QJsonObject` 中；
   "保存" = 构造最小合法题库过 `validateBank` + 写回内存节点 + 状态标记。
   ⚠️ `core/src/draft_store.cpp` 的 `DraftStore` 是**主程序（小窗刷题）的答题草稿**
   （`AppLocalDataLocation/drafts/<sha256(providerId)>/<sha256(attemptId)>.json`，version 2），
   与制作器编辑无关，不要混写。
3. **原 PDF 永不修改**：一切"改图" = 临时重渲染 PDF 页 + 新框裁 PNG。
4. **校对图（reviewAssets/reviewSourceImages）不进安装包**；只有正式附件（assets）打包。
5. **可编辑性矩阵**（所有题型统一，无题型区分）：

| 字段 | 可编辑？ | 途径 |
|---|---|---|
| 题干 `stem` | ✅ | QTextEdit；改后旧 `stemUnderlines` 整体清除 |
| 选项文本 `options[].text` | ✅（可增删，≥1 项，schema 要求 ≥2） | 每选项一行 QLineEdit + 添加/删除按钮 |
| 选项 id | ❌（badge 只读，新增自动取未占用的 a–z） | — |
| 选项图片 | 只能**重裁 bbox**，不能换图 | CropDialog（见 §3） |
| 答案 `answer.optionIds` | ✅（含答案库必填） | QLineEdit，按 `[,，\s]+` 分割 |
| 解析 `solution` | ✅（可空） | QPlainTextEdit |
| 下划线/填空 `stemUnderlines`/`underlines` | ✅（专用对话框选词） | "修正下划线/填空"按钮 |
| 图片区域 bbox | ✅（正式图） | CropDialog 重裁 |
| 题号 / 题型 / id / catalogId / materialId / source | ❌ | — |
| 材料正文 `body` | ❌（材料侧只支持下划线修正与图片重裁） | — |

   唯一全局限制：最终题库级 `hasAnswerKey` 仍决定答案/解析字段是否存在；输入阶段默认
   自动检测，人工“含答案/无答案”只作整库策略覆盖。

## 1. 识别结果的 UI 呈现（第三步"检查问题"）

### 1.1 树视图 `populateReview`（`:1975-2125`）

左 `QTreeWidget reviewTree_`（两列："材料 / 题目"、"问题"）：
- **顶层**：每份共享材料一行（soft 风险显示"资料待复核"）；"独立题目"节点；
  引用断裂时追加"引用断裂"节点（`:2060-2064`）。
- **题目行**：第一列 = `reviewQuestionTitle`（`:112-121`，章节前缀 + 题号，
  重号显示"原第 N 题 · 同号第 k 处"）；第二列 = hard 风险时的 `review.reason`（截 240 字）。
- **复选框 = 收录开关**：hard 默认不勾（`:2085-2088`，第二列红色 `#c94b4b`），
  其余默认勾选（自动收录）。
- 节点内数据：`UserRole` = 整题 JSON，`UserRole+1` = signals，`+2` = isHard，`+3` = isSoft。
- 筛选标签：`需要处理 N / 全部题目 N / 缺少答案 N / 疑似重复 N`（`:1327-1347`，
  无答案库隐藏"缺少答案"；`applyReviewFilter` `:2804-2839`）。
- 汇总条（`:2108-2120`）："✓ 已自动收录 N 项，没有必须处理的问题" 或
  "还有 M 项需要决定。未处理的题不会收录，不影响继续。"

### 1.2 右侧详情面板（`buildReviewPage` `:1385-1458`，填充 `showReviewQuestion` `:2359-2479`）

- 标题/状态（`:2430-2436`）："需要处理：&lt;reason&gt;" 或
  "已自动收录。图片、扫描内容和版式已处理；如有偏差可在下方修改。"
- **图片区**（`displayReviewAssets` `:2127-2195`）：`QLabel` 缩放宽 520 显示
  `reviewAssets_`（校对裁图，优先）或 `generatedAssets_`（正式附件）；
  多图时出现"原卷第 N 页"页选择器（`:2151-2161`）。
- **题干编辑器** `reviewStemEditor_`（`:1405-1411`，高 58-240px 自适应 `:2791-2802`）：
  `〔填空〕` ↔ `＿＿＿＿` 双向转换（`stemForReviewEditor`/`stemFromReviewEditor` `:213-224`）；
  `stemUnderlines` 用 `QTextEdit::ExtraSelection` 画真下划线（`:2440-2450`）。
- 选项区（每行 QLineEdit + 删除按钮，`:2302-2345`）；答案 QLineEdit
  （placeholder "例如 A；多选题填写 A、B"，`:1434-1436`）；解析 QPlainTextEdit。
- 按钮：**"保存并收录"**（hard）/ **"保存修改"**（soft）与 **"不收录本题"**（`:1444-1450`）。

### 1.3 每题的图片从哪来

正式 `stemImage` 仍在引擎阶段生成并进入 `assets`。普通文字题的“原卷题目”校对图改为
**按需懒渲染**：引擎侧 `describeLazySourceBlock()` 只根据文字锚点记录最多 4 页的
`reviewSegments{sourcePage,crop}`、稳定 path 与 `lazyReview=true`，写入 `reviewSourceImages`，
不在规则整理阶段生成 PNG，也不预填 `reviewAssets`。复核页选中题目时，
`StudioWindow::ensureReviewAssetBytes()` 才从原 PDF 渲染这些片段、纵向拼接并把当前一张 PNG
放入会话级 `reviewAssets_`。因此 600 题题本不会在进入复核页前同时持有 600 张校对图。
显示顺序仍为：原卷预览 → `stemImage` → 各选项 `image`，去重后展示。

## 2. 确认 / 拒绝（review 决策）机制——三级

1. **引擎自动分级**（`rule_based_generator.cpp:2041-2061`）：
   hard → `needsReviewQuestions`（默认不勾）；soft → 留 `questions`（默认勾、可核对）；ok → 直接收录。
2. **用户决策**：
   - **确认** `confirmCurrentReviewQuestion`（`:2703-2724`）：先 `saveCurrentReviewQuestion`，
     然后 `review.needsReview=false`、`reason="已人工确认"`、清 hard/soft 标志、勾选、
     行文本"已人工确认"，`advanceToNextReviewIssue()`（`:2770-2787`）自动跳下一个未处理 hard 题；
   - **拒绝** `excludeCurrentReviewQuestion`（`:2726-2739`）：取消勾选、行文本"暂不采用"，
     提示"重新勾选或确认本题即可恢复"；
   - 直接勾/取消勾选同样改变收录状态（统计 `:1651-1657`；状态刷新 `:2744-2753`）。
   - 复核页底部按钮实时显示："继续生成（收录 N 题）→"（`:1657`）。
3. **脏数据保护**：切题前/打包前 `commitOpenReviewQuestion`（`:2690-2701`，切题钩子 `:1463-1475`）——
   草稿校验失败时弹框"仍要继续吗？"，用户可放弃切换以保留编辑器内容。

诊断埋点：`review-draft-saved`（`:2646`）、`review-question-confirmed`（`:2719`）、
`review-question-excluded`（`:2734`）。回归测试 `tests/studio_review_ui_test.cpp` 覆盖
"确认一题后其余题不得退化"（`:126-131`）。

## 3. 手工编辑图片区域（bbox 重裁）——CropDialog

入口：详情面板图片标题后的 **"手动修正"** 按钮；按钮靠左保持在详情初始视口内，
不会因为较宽的题干/选项内容而藏到横向滚动区右端。仅复核的原卷预览显示为
**"调整原卷区域"**。只要有 `sourcePage>0` 与 `sourceDocument`，两者都可重新框选——
正式题图（stemImage/选项图/材料图）更新成品附件；`reviewOnly` 原卷预览只更新本次制作
会话内的 `reviewAssets/reviewSourceImages`，**不进入 bank.json 或最终题库包**。这使智能解析在
缺少可靠行级坐标、只能先显示整页原卷时，仍保留人工定位和文本校正入口。

### 3.1 流程 `recropReviewAsset`（`:2197-2230`）

1. 按 `asset.sourceDocument`（文件名）在 `sourcePaths_` 里找回原 PDF 路径（`:2200-2206`）；
   找不到 → 提示"请重新添加原题 PDF 后再次整理"（`:2207-2211`）；
2. `renderPdfReviewPage()`（`:408-429`）：`QPdfDocument` 按页面 point 尺寸 **×1.7** 栅格化，
   上限 1800×2400（`:416-418`）；QtPdf 返回的透明页面先由
   `flattenReviewPage()` 铺成白底不透明图，避免裁切画布出现黑底黑字；
3. 读取 asset 的两个归一化(0..1)框：`autoCrop`（规则引擎初始框）与 `crop`（用户上次框）
   （`:2218-2222`），均空回退 `(0.05,0.05,0.90,0.90)`；
4. 弹 `CropDialog`（`:336-389`）：
   - 只展示**当前定位附近区域**——`cropContextAround()`（`:391-398`）在原框外加
     水平 ≥8% / 垂直 ≥10% padding；
   - 说明文字："这里仅显示当前定位附近的原卷区域，粉色框是当前裁切框。拖拽重新框选要保留的
     区域；不会上传原卷或图片。"（`:343-345`）
   - 三个按钮：**"恢复当前定位"**（重置到 `autoCrop`，`:355,358-359`）、取消、
     **"使用此裁切"**（框宽/高 < 0.01 时警告"裁切范围过小"并拒绝，`:361-368`）。

### 3.2 实现控件：自定义 QWidget（**不是 QGraphicsView**）

`CropCanvas`（`:269-334`）：
- `paintEvent` 把整页 `QImage` 画到控件上，再画粉色 `#ff4d85` 边框 + 30% 透明填充选区矩形（`:282-293`）；
- 鼠标交互 = **整体拖框**（左键按下定起点、移动定终点，`:295-323`），坐标归一化 0..1（`:326-329`）；
- **没有句柄、没有平移缩放、没有框内微调**——只能整框重画（可优化点，见 [todo](todo.md)）；
- 控件尺寸 = 原图按 `QSize(980,680)` 等比缩小（`:273-274`）。

### 3.3 裁剪结果落盘 `commitReviewCrop`（`:2232-2284`）

1. 新框从整页 `QImage` 裁像素 → PNG（`:2234-2244`）；
2. 正式附件覆盖写入 `generatedAssets_[原 asset.path]`——路径不变、字节换新，
   因此 bank.json 的 `path` 不需要改，导出时打进去的就是新图；**仅复核预览**则写回
   `reviewAssets_` 与 `reviewSourceImages_`，不升级为正式附件；
3. asset 描述插入/更新 `crop`（用户框），`autoCrop` 保留为规则初始值（`:2247-2248`）；
4. 回写：材料 → 替换 `material.images[]` 同 path 条目并同步 `generatedMaterials_`（`:2259-2270`）；
   题目 → 替换 `stemImage`（`:2272`）或遍历 `options[].image` 命中同 path（`:2273-2279`）；
   写回树节点 `UserRole` 并刷新详情面板（`:2281-2282`）；
5. 提示："已从原卷第 N 页更新截图；保存草稿后再确认本题。"

## 4. 文本编辑与草稿校验 `saveCurrentReviewQuestion`（`:2577-2649`）

1. 收集编辑器内容写回整题 JSON：stem（`:2603`）、options（`reviewOptions` `:2347-2357` → `:2604`，
   任一选项文本为空 → 整体保存失败 `:2350-2352`）、answer/solution（`:2605-2620`，
   无答案库移除两字段 `:2617-2619`）；
2. **关键**：先构造最小合法题库走完整 Schema 校验——`makeReviewDraftBank()`
   （`src/review_draft_bank.cpp:5-20`）：
   ```cpp
   {"schemaVersion":3, "title":"复核草稿", "answerPolicy": included|none,
    "catalogs":[{"id":"generated","title":"复核草稿","practice":{"mode":"all"}}],
    "questions":[question], "materials":[引用的材料]}
   ```
   然后 `quizpane::validateBank(bank)`（`:2632-2638`），失败 → "草稿尚不完整" 阻止保存。
   （`review_draft_bank.hpp:8-11` 注释：集中构造，避免草稿校验与最终打包结构偏离；
   测试 `tests/review_draft_bank_test.cpp`。）
3. 通过 → 写回树节点 `UserRole`（`:2639`），行文本改"草稿已保存 · 仍待确认"或"已人工确认"（`:2641-2642`）。
4. 脏检查 `reviewQuestionIsDirty`（`:2651-2688`）+ 切题/打包前强制提交 `commitOpenReviewQuestion`（`:2690-2701`）。

**下划线修正**：`addManualMaterialUnderline`（`:2481-2575`）——选中文本 → 合并写入
`{start,length}` 数组（`:2529-2570`），支持"清除全部"（`:2513,2527`）。
按钮仅在题干含 `〔填空〕`、有 `stemUnderlines`、或信号 `stem/material-layout:underline-or-blank`
时出现（`:2411-2414`、`:2375-2378`）；改题干前必须先保存（`:2484-2488`）。
**题干一旦改动，旧 `stemUnderlines` 在用户确认后整体清除**（"原下划线位置可能失效"，`:2592-2601`）。

## 6. 数据流全景（识别 → 编辑 → 导出）

```
源文件 + 答案配对
  → SourceMaterialGroup{questionPath, answerPath, answerPolicy,
      mineruZipPath, mineruAnswerZipPath}  (generation_workflow.hpp:30-40)
  → GenerationWorkflow::startRuleBased (generation_workflow.cpp:25-147)
      ├─ 提取：本地 ExtractorRegistry 或 MinerU 云 ZIP
      │   （adaptMineruZip → 同一个 ExtractedDocument, generation_workflow.cpp:67-83）
      └─ RuleBasedBankGenerator::generate → ReviewResult (rule_based_generator.cpp:2198-2787)
  → emit questionsReady → populateReview (studio_window.cpp:1975-2125)
      ├─ 窗口成员：generatedMaterials_/generatedQuestions_/reviewQuestions_
      │   generatedAssets_/reviewSourceImages_/reviewAssets_（普通题校对图按需填充）
      └─ 树节点 UserRole = 题目 JSON (:2081)  ← 用户可编辑的中间结构
  → 编辑：
      ├─ 文本/选项/答案/解析 → saveCurrentReviewQuestion 写回节点 (:2639)
      └─ 重裁图 → commitReviewCrop: generatedAssets_[path]=新PNG + asset 描述更新 (:2246-2281)
  → packageProvider (:2841-3005)：
      收集勾选题(按识别顺序 stable_sort) → 组 bank → validateBank
      → manifest → ZIP → 三重自检 → 安装 → handoff
```

映射要点：
- 编辑**不产生新 id/新结构**，只原地改字段；
- 改题干清 `stemUnderlines`（`:2600`）；重裁图只换 `crop`/字节、不换 `path`（`:2246-2248`）；
- 未处理（未勾选且 hard）的题静默不收录，但不阻断导出（`refreshReviewDecisionState` `:2741-2768`）。
- 用户确认启动下一次整理后，`discardPreviousGenerationForNewTask()` 会先断开当前树节点指针，
  再清空旧题目树、`generatedAssets_`、`reviewAssets_`、`reviewSourceImages_` 和待裁切页面；
  Token/输入预检未通过时不清理，避免一次误操作丢掉仍在复核的结果。

## 7. 导出打包 `packageProvider`（`:2841-3005`）

1. `commitOpenReviewQuestion("继续打包")`（`:2843`）；
2. 收集勾选题（`:2855-2866`），空 → "至少需要采纳一道题"（`:2867-2872`）；按识别顺序排序（`:2873-2877`）；
3. 组 bank（`:2894-2898`）：
   ```json
   {"schemaVersion":3, "title":"<题库名>",
    "answerPolicy":"included"|"none",
    "catalogs":[{"id":"generated","title":"<题库名>",
                 "practice":{"mode":"all"|"sequential","questionCount":5/10/15}}],
    "questions":[...], "materials":[...仅被引用...]}
   ```
4. `quizpane::validateBank`（`:2900`，实现 `bank_validator.cpp:321-458`；
   失败弹"题库校验失败" + `package-validation-failed` 事件）；
5. **manifest**（`:2908-2916`）：
   ```json
   {"manifestVersion":2, "id":"local.generated.<sha256(标题)前16位hex>",
    "name":"<题库名>", "version":"1.0.<epoch秒>", "kind":"declarative",
    "runtime":{"format":"quizpane.bank+json","schemaVersion":3,"entry":"content/bank.json"},
    "permissions":{"network":false}}
   ```
6. **ZIP**（`:2917-2934`）：`generated.quizpane-provider`（QTemporaryDir 内）=
   `manifest.json` + `content/bank.json` + **`generatedAssets_` 全部 PNG**（`:2927-2928`，键即 `assets/...` 路径）；
   `reviewAssets_`/`reviewSourceImages_` **不打包**；
7. **三重自检**：`ProviderInstaller::inspect`（`:2935-2943`）→ 从 ZIP 重新读出 manifest/bank（`:2946-2954`）
   → 落临时 staging 再 `DeclarativeProvider::load`（`:2955-2971`）；
8. **安装 + 交接**：`installer.install`（`:2972-2976`）→ 写小窗刷题的 `provider/lastLibraryPath`（`:2980-2982`）
   → `handoffProviderToRunningApp`（运行中的小窗直接切题）失败则 `launchQuizPaneForProvider`
   带 `--provider <entryPath>` 启动主程序（`:149-180, 2984-2992`）→ 关窗（`:3004`）。

## 8. 校验器 vs JSON Schema（权威契约）

`bank_validator.cpp` 相对 schema 文件的加强/差异：
- 白名单键校验防多余字段（`hasOnlyKeys` `:34-38,367-384`）；
- schemaVersion=3 强制保留 `source.questionNumber`：可为正整数，或 ≤40 字的非空字符串；
  兼容旧版整数题号，也能无损保存 `1-1`、`（一）` 等新版题号；
- **`validAsset` 放行 `sourceDocument/sourcePage/autoCrop/crop` 四个附加字段**（`:73-92`），
  而 schema 的 `$defs.asset` 是 `additionalProperties:false` 只允许 `path/alt`（`68-76`）——
  **运行时以 C++ 校验器为准**（制作器/CLI 都调 `validateBank`）；
- 多选语义：`answerPolicy=included` 时 `solution` 必填（`:407-409`）；
